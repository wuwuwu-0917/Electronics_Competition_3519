# 车载平衡滚球运动控制系统 — 视觉部分交接文档

## 赛题背景

**2026 全国大学生电子设计竞赛（TI 杯赛区）H 题：车载平衡滚球运动控制系统**

核心任务：通过视觉摄像头（MaixCAM2）检测钢球在管道上的实时位置，利用 PWM 直驱舵机控制管道倾斜角度，使钢球稳定在管道中心。

## 已实现功能

### 1. 绿色管道透视矫正
- 上电自动识别绿色管道（LAB 色域阈值）
- 四点透视变换，将倾斜管道铺平为俯视图
- 只在第一帧执行一次，后续复用锁定角点

### 2. YOLO 钢球检测 + Kalman 追踪
- YOLOv5 实时推理钢球位置
- 单球 Kalman 追踪器（1D Kalman × 2，位置 + 速度估计）
- 贪心匹配 + coast 机制（丢帧补全）
- 前向预测补偿 NPU 推理延迟
- 追踪位置映射到 warp 俯视图，转为 cm 坐标

### 3. 双模式 PD 控制器（核心）
#### 两种模式根据球的位置和速度自动切换（带滞后防抖）

| | 稳态模式 (S) | 扰动模式 (D) |
|---|---|---|
| **触发条件** | \|err\|<1.5 **且** \|vel\|<5 | \|err\|>2.5 **或** \|vel\|>10 |
| **定位** | 近中心 + 慢速 | 偏离远 或 跑得快 |
| **KP** | 8.0 | 10.0 |
| **KD** | 8.0 | 12.0 |
| **死区** | ±0.1cm | 无 |
| **D 上限** | ±80° | ±120° |
| **速率限制** | 400°/s | 900°/s |
| **I 项** | 有 (慢积) | 清零 |
| **策略** | 精细修正 + 消静差 | 暴力刹车 + 全力推回 |

#### I 项参数（仅稳态）
- 激活条件：\|err\|<2.0cm 且 \|vel\|<5cm/s
- 积分速率：5.0 deg/(s·cm)
- 上限：±25°
- 不满足条件时衰减系数：0.85/帧

### 4. IMU 加速度前馈
- **仅加速时启用**：acc_x > 0.8 m/s²
- **减速不用 FF**：IMU 响应快于球的运动，提前反向反而帮倒忙
- 公式：`FF = -atan2(acc_x, acc_z) × 57.3`（纯物理推导，K=1.0）
- 上限：±45°

### 5. 三模式触摸切换
- **模式 1**：双模式 PD（正常工作模式）
- **模式 2**：舵机 60°↔120° 来回摆动（2 秒周期，测试舵机）
- **模式 3**：舵机固定 90° 不动作（自由滚动测试）
- MaixCAM 触摸屏底部 50px 按钮栏切换

### 6. Web 推流 + 录像
- MJPEG 实时视频流
- 浏览器端录像控制（开始/停止/下载/删除）
- 录像文件 `.mjpeg` 格式，可回放、可跳转进度条

### 7. UART 数据发送
- 组包格式：`AA 55 | pos_cm(2B LE) | CRC16(2B LE) | DD`
- 位置精度：厘米 × 100

## 当前已知问题（2026-07-31）

### 问题 1：扰动后球无法归零，卡在 1.5~3cm（**严重**）

**现象**：每轮加减速扰动后，球在 D 模式下停在约 2cm 处振荡，迟迟无法回到中心。

**量化数据**（最新 ball_log.csv，773 帧）：
- 33% 的帧（255 帧）处在此状态：D 模式、偏差 1.5~3cm、低速度
- 球在 2cm 附近反复振荡，P=20° 应该足够推回但实际推不动
- I 项在 D 模式下被清零，没有任何力来消除残余偏差

**根因分析**：
1. **D 模式缺 I 项**：球卡在 1.5~3cm 时无法退出 D 模式（需要 err<1.5），而 D 模式 I=0，无法消除静差
2. **死区效应**：即使退出到 S 模式，S_DB=0.1cm 死区内 P=0，全靠 I 推，I 速率有限
3. **可能的机械死区**：舵机-管道连杆可能有间隙，小角度指令不产生实际倾斜

**建议修复方向**：
- 方案 A：在 D 模式也加入小 I 项（速率减半），让球能推过 SW_EXIT_ERR 门槛
- 方案 B：降低 SW_EXIT_ERR 从 1.5 到 1.0，让球更早进入 S 模式获得 I 项
- 方案 C：在 D 模式 \|err\|<2.5 时，允许 I 项以 1/2 速率累积

### 问题 2：减速时 FF 时序问题（中等）

**现象**：IMU 检测刹车（毫秒级）远快于刹车力传导到球上（数十毫秒），若提前 FF 反向会导致"反早"。

**当前处理**：减速时 FF=0，纯靠 PID 响应。

**副作用**：减速时球完全没有预判补偿，完全依赖 PID 在球被推动后再反应。球会先被推出一段距离才触发扰动模式刹车。

**建议修复方向**：
- 考虑用延时 FF：检测到刹车后延迟 2~3 帧再施放 FF
- 或等球速超过某个阈值（如 3cm/s）再开 FF

### 问题 3：舵机频繁触限（中等）

**现象**：舵机经常打到 20° 和 160° 极限位置，说明 PID 想要更大的倾斜角度。

**建议修复方向**：
- 检查机械结构，确认能否进一步扩大舵机行程
- 若机械允许，可将范围扩至 10°~170°

## 使用方法

### 启动
1. 将 `main_yolo.py` 与 `model_310357.mud` 放入 MaixCAM2
2. 上电，舵机自动归中 90°
3. 等待绿色管道识别（串口打印 `Green tube locked!`）
4. 自动进入模式 1 双模 PD 控制

### 模式切换
- 触摸屏幕底部按钮栏切换 M1/M2/M3
- 或修改代码 `CURRENT_MODE = 1` (约第 108 行) 重新上电

### Web 监控
- 浏览器打开 `http://192.168.43.130:5000`
- 实时画面 + 设备端录像 + 录像回放

### 日志分析
- `ball_log.csv` 位于 `/root/ball_log.csv`
- 下载后用 Excel 打开，可直接画图分析
- 列含义：`t_ms, ball_cm, vel_cms, acc_x, acc_z, servo_ang, P, D, I, FF, fps, mode`

## 设计演进关键节点

1. **v1-v3**：串级 PID → 单环 PID（消除符号冲突），基础参数调优
2. **v4-v6**：I 项从连续积分改为自适应（近中心禁积防极限环），加预测性刹车
3. **v7-v8**：引入双速系统——Kalman 原速做判断（零滞后）
4. **v9-v13**：去掉 EMA 改为零滞后直驱，双模 KD 逐步优化
5. **v14-v16**：完全重写为干净的双模式 PD + 慢速 I，扰动全力输出
6. **v17-v20**：加入 IMU 前馈（运动补偿），全帧日志记录
7. **v21-v25**：FF 参数多轮调整（K=0.5→2.0→1.0），加入新鲜度检查
8. **v26-v30**：减速特殊处理（FF 拉满→不预判→纯 PID），来回试验
9. **当前版本**：回归干净双模式 PD + 加速 FF + 减速无 FF

## 注意事项

1. **舵机限速**：稳态 400°/s，扰动 900°/s
2. **管道颜色**：若更换管道颜色，需修改 `GREEN_THRESHOLD`（LAB 色域）
3. **模型文件**：`model_310357.mud` 路径回退为 `/root/models/mymodel/steelball/model_me2/`
4. **D 项零滞后**：直接使用 Kalman 原始速度，未加任何滤波
5. **FF 仅加速**：减速不用 FF，IMU 快于球运动会"反早"
6. **I 项仅稳态**：D 模式 I=0，球若卡在 1.5~2.5cm 会因无法退出 D 模式而得不到 I 项推力
