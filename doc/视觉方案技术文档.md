# 车载平衡滚球运动控制系统 —— 视觉方案技术文档

## 1. 系统概述

本视觉方案基于 **MaixCAM2 AI 摄像头** + **YOLOv5 目标检测** + **透视矫正 + Kalman 追踪**，实现对摆杆管道内钢球位置的实时、高精度检测，并通过 Wi-Fi MJPEG 推流实现无线画面传输与录像回放。

### 1.1 核心指标

| 指标 | 数值 |
|---|---|
| 检测帧率 | ~60 FPS |
| 位置分辨率 | ≤0.1cm（配合摆杆刻度线） |
| 检测延迟 | <2 帧（含 Kalman 前向预测补偿） |
| 无线推流延迟 | <100ms（局域网 MJPEG） |
| 追踪保持 | 丢帧 ≤5 帧不中断 |

### 1.2 硬件组成

- **摄像头模块**: Sipeed MaixCAM2（搭载 M0+ 级别 NPU）
- **镜头**: 固定在摆杆正上方，俯瞰管道
- **补光**: GPIO 控制 LED 常亮补光，增强钢球反光
- **传输**: Wi-Fi 局域网 MJPEG 推流（HTTP Server 端口 5000）
- **控制通信**: UART 串口（115200bps）向 MCU 发送钢球位置数据
- **显示**: MaixCAM2 自带 LCD 屏实时显示检测画面
- **外部显示**: 任意浏览器设备（PC/平板/手机）接入同一 Wi-Fi 即可查看

## 2. 视觉检测流程

### 2.1 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  MaixCAM2 摄像头 (固定于摆杆正上方)                        │
│       │                                                  │
│       ▼                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐           │
│  │ 绿管检测  │ → │ 透视矫正  │ → │ YOLO检测 │           │
│  │ (仅一次)  │    │ (每帧)   │    │ (每帧)   │           │
│  └──────────┘    └──────────┘    └──────────┘           │
│                                       │                  │
│                                       ▼                  │
│                                  ┌──────────┐           │
│                                  │ Kalman   │           │
│                                  │ 追踪+预测 │           │
│                                  └──────────┘           │
│                                       │                  │
│                    ┌──────────────────┼──────────────┐   │
│                    ▼                  ▼              ▼   │
│               UART 发送          LCD 显示      Wi-Fi推流 │
│               (给MCU)          (本地画面)    (浏览器查看) │
└─────────────────────────────────────────────────────────┘
```

### 2.2 阶段一：绿色管道检测与透视矫正（上电执行一次）

**目的**: 摄像头不一定能正对管道，存在透视倾斜。通过识别绿色管道区域，将倾斜画面矫正为俯视平面图。

**步骤**:
1. 摄像头采集一帧图像（YOLO 模型原生分辨率，如 224×224）
2. 在 LAB 色彩空间进行色块检测 (`find_blobs`)，提取绿色管道区域
3. 利用 `mini_corners()` 获取绿色区域的四个角点
4. 对四个角点进行排序 → 左上、右上、右下、左下
5. 根据角点坐标计算透视变换的目标尺寸
6. 生成透视变换矩阵，将管道区域铺平为矩形

**关键技术参数**:

| 参数 | 值 |
|---|---|
| 颜色空间 | LAB |
| 绿色阈值 | L:(0,100), A:(-128,-36), B:(-128,127) |
| 最小色块面积 | 150 像素 |
| 检测时机 | 上电检测一次，锁定后不再重复 |

**为什么只检测一次**:
- 摄像头与管道的相对位置固定不变
- 反复检测会增加不必要的计算开销
- 锁定后可确保参考坐标系稳定

### 2.3 阶段二：透视矫正后的参考标尺

矫正后的矩形画面对应实际管道长度 25cm（`PIPE_LENGTH`）。

**参考线**:
- **三条黄色虚线**: 中心线（0cm）、中心+5cm、中心-5cm
- **一条红色水平实线**: 管道水平中线（钢球运动轨迹线）
- **红色实心圆点**: 钢球当前位置标记

**位置换算公式**:

```python
# 球心在 warp 图上的 x 坐标 → 实际厘米偏移
ball_cm = (ball_warp_x - W/2) * PIPE_LENGTH / W
```

其中 `W` 为 warp 图宽度，`PIPE_LENGTH = 25.0cm`。

### 2.4 阶段三：YOLOv5 钢球检测

**模型**: 自训练 YOLOv5 模型（`model_310357.mud`），在 MaixCAM2 NPU 上推理。

| 参数 | 值 |
|---|---|
| 输入分辨率 | 模型原生分辨率（如 224×224） |
| 置信度阈值 | 0.6 |
| IoU 阈值 (NMS) | 0.45 |
| 检测目标类别 | "sb"（steel ball） |
| 推理设备 | MaixCAM2 NPU（硬件加速） |

**关键设计决策**:
1. **YOLO 在原图上推理，不做 warp 后再检测**: warp 后的图像尺寸与模型输入不匹配，会导致内部 resize 失真，造成检测框断续。原图推理保持尺寸一致，检测稳定。
2. **仅保留最高置信度目标**: 单球场景中只取最高分的检测结果，避免假阳性干扰。

### 2.5 阶段四：Kalman 追踪 + 前向预测

**为什么需要追踪**:
- YOLO 检测偶有丢帧（遮挡、光照变化、运动模糊）
- 检测本身有 NPU 推理延迟（约 1 帧）
- 需要平滑的位置输出来控制小车

**追踪器设计**:

采用两个一维 Kalman 滤波器（x 和 y 方向独立），状态向量 `[position, velocity]`。

```python
class Kalman1D:
    """恒速模型, 状态: [pos, vel]"""
    
    def predict(self):
        # 状态预测: pos += vel
        self.pos += self.vel
        # 协方差更新 (含过程噪声)
        
    def update(self, measurement):
        # 测量更新: 卡尔曼增益 K = P*H^T / (H*P*H^T + R)
        # 状态修正: pos += K * (measurement - pos)
        # 协方差更新: P = (I - KH)P
```

**追踪器参数**:

| 参数 | 值 | 说明 |
|---|---|---|
| `MATCH_DIST` | 80px | 检测框与追踪位置的最大匹配距离 |
| `COAST_MAX` | 5帧 | 丢帧后轨迹保持的最大帧数 |
| `CONFIRM_HITS` | 1帧 | 首帧即确认（最快响应） |
| `PREDICT_AHEAD` | 1帧 | 前向预测帧数（补偿 NPU 延迟） |

**前向预测 + 防过冲机制**:

```python
def output(self):
    # 前向预测: 补偿检测延迟
    px = kalman_pos + kalman_vel * PREDICT_AHEAD
    
    # 防过冲钳制: 预测值不能超过最新检测位置 ± 半个球宽
    limit = max(ball_width * 0.6, 5.0)
    if velocity > 0:
        px = min(px, last_detection + limit)  # 正向运动, 上限钳制
    else:
        px = max(px, last_detection - limit)  # 反向运动, 下限钳制
```

**效果**:
- **平稳运动**: 预测值超前检测位置，补偿延迟 → 响应更快
- **急停/急转**: 钳制机制在 0.5~1 帧内将预测值拉回检测位置 → 不过冲

### 2.6 阶段五：坐标映射（原图 → warp 图）

由于 YOLO 在原图上检测，而位置计算需要基于 warp 图（俯视平面），需要将球心坐标从原图映射到 warp 图。

**映射方法：双线性插值**

```python
def _point_to_warp(px, py, TL, TR, BR, BL, dst_w, dst_h):
    # 1. 在 px 处求上下边界的 y → 得到垂直比例 v
    top_y = TL.y + (TR.y - TL.y) * (px - TL.x) / (TR.x - TL.x)
    bot_y = BL.y + (BR.y - BL.y) * (px - BL.x) / (BR.x - BL.x)
    v = (py - top_y) / (bot_y - top_y)
    
    # 2. 在 py 处求左右边界的 x → 得到水平比例 u
    left_x  = TL.x + (BL.x - TL.x) * (py - TL.y) / (BL.y - TL.y)
    right_x = TR.x + (BR.x - TR.x) * (py - TR.y) / (BR.y - TR.y)
    u = (px - left_x) / (right_x - left_x)
    
    # 3. 映射到 warp 图坐标
    warp_x = u * (dst_w - 1)
    warp_y = v * (dst_h - 1)
```

该映射等价于对单点执行 `image.perspective()` 的逆运算，确保球心在 warp 图上的位置精确对应管道上的实际位置。

### 2.7 阶段六：数据输出

**UART 串口输出**:

每帧通过 UART 发送 7 字节数据包给小车 MCU：

```
┌─────┬─────┬───────────────────┬─────────────────┬─────┐
│ AA  │ 55  │  pos_cm (2B LE)   │  CRC16 (2B LE)  │ DD  │
│帧头  │帧头  │  厘米×100 (有符号) │  CRC16-CCITT    │帧尾  │
└─────┴─────┴───────────────────┴─────────────────┴─────┘
```

- `pos_cm`: 钢球偏离管道中心的距离，单位 cm，分辨率 0.01cm
- CRC16-CCITT (XMODEM) 校验，确保数据传输可靠性
- 波特率：115200bps

## 3. Web 推流与录像系统

### 3.1 系统架构

```
MaixCAM2 (HTTP Server :5000)
    │
    ├── /video_feed     → MJPEG 实时推流
    ├── /               → HTML 控制页面
    ├── /api/record/start  → 开始录像
    ├── /api/record/stop   → 停止录像
    ├── /api/recordings    → 录像列表 (含帧数+时长)
    ├── /play/<file>       → 录像回放 (MJPEG, 支持 ?start=N 跳转)
    └── /snapshot          → 单帧截图
```

### 3.2 技术特点

| 特性 | 实现方式 |
|---|---|
| 实时推流 | MJPEG (`multipart/x-mixed-replace`)，浏览器原生支持 |
| 录像存储 | 自定义 `.mjpeg` 格式，含 14 字节文件头 |
| 文件头结构 | `MJPEG`(5B) + `version`(1B) + `frame_count`(4B) + `elapsed_ms`(4B) |
| 推流帧率 | 每 2 帧编码一次 JPEG（跳帧降负载，检测不受影响） |
| 跨平台访问 | 任意浏览器接入同一 Wi-Fi 即可查看、录像、回放 |

### 3.3 录像回放功能

- **进度条**: 基于实际帧数，支持拖拽跳转
- **时间显示**: 基于真实录制时长 (`elapsed_ms`)，不受跳帧影响
- **帧精确定位**: 服务器端 `?start=N` 参数跳过前 N 帧，从指定位置开始推流
- **播放速度**: 30 FPS 固定播放（每帧间隔 33ms）

## 4. 性能分析

### 4.1 延迟分析

```
总延迟 = 摄像头采集(<1ms) + NPU推理(~15ms) + Kalman处理(<1ms) + 前向预测补偿(-16ms)
       ≈ <1ms (通过预测补偿实现零延迟输出)
```

- NPU 推理约 15ms（~60FPS），Kalman 前向预测 1 帧恰好补偿该延迟
- UART 发送延迟 <1ms（115200bps 下 7 字节 ≈ 0.6ms）

### 4.2 帧率瓶颈

| 环节 | 耗时 | 说明 |
|---|---|---|
| `cam.read()` | <1ms | 硬件抓帧 |
| `detector.detect()` | ~15ms | NPU 推理，主要瓶颈 |
| `img.perspective()` | ~1ms | 硬件加速透视变换 |
| Kalman 追踪 | <1ms | 纯 Python 数学运算 |
| `dis.show()` | ~2ms | LCD 垂直同步（60Hz） |
| JPEG 编码 | ~8ms | 每 2 帧执行一次 |
| **总计** | **~25ms** | **≈ 40~60 FPS** |

### 4.3 精度分析

- **YOLO 检测精度**: 摆杆内径 1cm，钢球直径约 1cm，在 224×224 像素画面中球约 10-15px
- **追踪平滑**: Kalman 滤波 + 前向预测 + 防过冲钳制确保输出稳定
- **坐标映射**: 双线性插值透视映射，消除透视误差
- **位置分辨率**: `PIPE_LENGTH / W = 25cm / 224px ≈ 0.11cm/px`，配合校准偏移可达到 0.1cm 分辨率

## 5. 关键技术创新点

1. **检测与矫正分离架构**: YOLO 在原图上检测（保持模型精度），透视矫正仅用于坐标映射和显示参考线，避免 warp 图像尺寸不匹配导致的检测不稳定。

2. **Kalman 前向预测 + 钳制**: 兼具快速响应与过冲防护，在 NPU 推理延迟和急停抖动之间取得平衡。

3. **双线性透视点映射**: 对单点坐标做双线性插值映射到 warp 图，避免对整图做 YOLO 推理，既保证了坐标精度又不引入检测不稳定。

4. **MJPEG 录像 + 帧精确定位**: 在文件头存储帧数和真实时长，支持进度条拖拽跳转，解决了 MJPEG 格式无时间信息的固有问题。

5. **NPU 全流程优化**: YOLO 推理在 NPU 上执行，透视变换和图像处理利用硬件加速，CPU 仅处理轻量 Kalman 数学运算和通信协议。
